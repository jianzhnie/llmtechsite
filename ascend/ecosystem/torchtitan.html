TorchTitan ​

TorchTitan 是一个 PyTorch 原生平台，用于快速实验以及生成式 AI 模型的大规模预训练与后训练。它被设计为 PyTorch 原生技术的最小化、洁净式实现，并为用户需求提供灵活的扩展点。这使得 TorchTitan 在学术界和工业界的研究与生产中获得了广泛采用。

1. 新模型支持 ​

SOTA 模型支持对训练框架的成功至关重要，TorchTitan 致力于在开放权重架构方面始终提供最新进展。TorchTitan 新增了 PyTorch 原生支持，覆盖 Muse Spark Open、Muse Glimmer、Qwen3-VL 和 Qwen3.5、Kimi K2.7、Kimi K3 以及 DeepSeek-V4。这些都是完整的训练栈集成，支持 TorchTitan 的 5D 并行栈。这项工作还引入了一个可组合的配置系统，围绕带类型标注的 Python recipe、模型配置变换和有针对性的组件覆盖构建。用户可以更改并行化策略、模型组件或特定硬件的内核，而无需维护单独的模型 fork。同一套接口集成了来自 Attention Gym 的优化内核，包括 Gated DeltaNet、Kimi Delta Attention 和稀疏注意力内核，以及可选启用的 Helion 内核（如融合 RoPE），同时保持与 torch.compile 的兼容。

每一个前沿模型都扩展了 TorchTitan 可复用的工具包，从多模态数据流水线、样本打包、共享视觉组件和 Hugging Face checkpoint 互操作，到可组合的 5D 并行、声明式分片、优化的 Attention Gym 与 Helion 内核，以及严格的数值验证。开发者可以在这个基础上，完全用原生 PyTorch，更快地把新发布的架构带到经过验证、可扩展的训练中。

2. 开箱即用性能改进 ​

过去一年，TorchTitan 为 MoE 模型交付了大规模性能改进，围绕三个重点领域：更快的内核以提升算力利用率、最大化通信-计算重叠，以及对内存的细粒度控制。

local_compile 无需绑定全图或整块的图追踪，也能带来原生 torch.compile 的收益，允许用户选择性地优化关键区域，同时保持数值精度，而无需维护自定义内核。

在内存管理方面，torch_remat 提供现代激活检查点 API，对重计算区域进行细粒度控制，避免 CPU 开销和自定义算子包装器要求。

在分布式计算和扩展方面，Dist-MoE 为 NVIDIA SM100+ GPU 提供融合通信-计算内核，并对动态张量做激活打包，以保持完全可被 CUDA Graph 捕获。同时，完全重构的 流水线并行 包提供可被 CUDA Graph 捕获的确定性执行，并带有用户控制旋钮，在组合 FSDP 与流水线并行时最大化重叠。

最后，TorchTitan overrides 让专门的模型特定内核——如融合 MLA、融合 SwiGLU 和融合 Complex RoPE——能干净地集成进来，而不牺牲代码的简洁性和可维护性。

3. FlexShard ​

TorchTitan 利用 FSDP2 对模型状态（参数、梯度和优化器）做按行或按列分片。然而，更新的特性——如分布式 Muon 优化器和参数的分块量化——需要或受益于 FSDP2 无法实现的更特殊的分片策略。为此，TorchTitan 现在集成了 FlexShard ——一个新的数据并行库，用于分片模型和优化器状态。FlexShard 提供以 bucket 为中心的 API，每个参数 bucket 都可以按自定义的 Placement 策略分片，并具有优化的运行时，将 bucket 通信与计算重叠。FlexShard 提供与 FSDP1、FSDP2 类似的 placement，此外还提供新的 placement，如 Owned（一个 rank 拥有整个参数）和 BlockShard（允许 2D tile 对齐的分片）。

FlexShard 让 TorchTitan 能够高效支持分布式 Muon 优化器：用 Muon 优化的参数按 Owned 和 BlockShard placement 分片——消除了执行优化器更新之前的 AllGather 集合通信。在 256 张 H100 上跑 DeepSeek-V3 时，与同等的纯 FSDP 实现相比，优化器耗时最多减少 79%。

FlexShard 还让 TorchTitan 支持分块量化参数的 AllGather：按集合通信收集 FP8 量化参数，通信量减少约 50%。使用 FSDP2 时，由于分片边界未必与分块量化边界对齐——我们要么被迫以 BF16 收集参数（增加通信量），要么执行 FP8 all-gather 但要为量化缩放因子额外做集合通信。FlexShard 的 BlockShard placement 让 TorchTitan 两全其美——收集量化参数时无需为缩放因子额外通信，因为分片策略在定义上就与量化方案对齐：在 256 张 H100 上跑 Llama 3 405B 时，端到端训练步时间最多减少 20%。

4. GraphTrainer ​

GraphTrainer 是 TorchTitan 中的图模式训练方案，提供围绕显式训练图构建的另一种执行模型。

TorchTitan 同时支持基于图和基于 eager 的训练路径，数值结果逐位匹配。基于图的训练后端支持在 eager 执行中难以表达的高级图级优化，包括跨模块融合、显式图级调试，以及对异构 AI 硬件加速器的定制支持。

5. 分布式基础设施 ​

TorchTitan 是 PyTorch 中新通信特性发布时的重要验证场。大规模训练会给通信栈的每一部分（初始化、集合通信、故障处理和内存注册）带来压力，这使 TorchTitan 成为一个要求苛刻的试验场。

新的 NCCL 后端，已在 TorchTitan 上验证： 在 PyTorch 2.14 中，来自 torchcomms 的 NCCL 实现被移植到 c10d，作为一个新的、可选启用的 NCCL 后端。这让我们能更快地启用新特性。它被设计为现有后端的直接替换，并以标准 "nccl" 后端名注册。与现有后端相比，它新增：

  • 单边 RMA 窗口
  • 原地进程组重配置，用于容错
  • eager 通信器初始化（在 PyTorch 2.15 中）
  • 对 NCCL shrink/grow 和 suspend/resume API 的直接访问（raw access）

对称内存： 对称内存继续是 TorchTitan 重要的性能杠杆。TorchTitan 的 MoE 层现在可以跑在 Dist-MoE 上——一个新开源的分布式混合专家库，并为 NVIDIA Blackwell GPU 提供开箱即用的 DeepSeek-V3 recipe。Dist-MoE 通过对称内存在专家之间移动 token，并将该通信与专家计算融合。TorchTitan 中的 FSDP 也可以从对称内存池分配通信缓冲区。这让 NCCL 能够使用其对称内存内核实现，包括在启用 NCCL zero-CTA 策略时使用 copy-engine all-gather。

6. Checkpoint 机制 ​

TorchTitan 集成了对新分布式 checkpoint 库 torch_checkpointing 的支持。这个新库在默认的 torch.distributed.checkpointing（DCPv1）保存中移除了每次保存的同步。我们在第一次保存之前做一次集合通信（在默认进程组上）以共享元数据；第一次保存之后，不再做任何集合通信。

当预训练规模增长到超过 16k rank 时，之前用 GLOO 集合通信实现同步的方法随节点数扩展不佳。torch_checkpointing 每次保存只运行轻量 barrier 的方法在这种规模下胜出。

我们还改进了 DCPv1 内的其他方面，例如在一次 torch.save 中保存整个 checkpoint 项（如模型、优化器等），而不是对每个单独张量调用 torch.save，并让自定义组件可插拔（例如编写为你的基础设施优化的自定义存储后端）。

在 512 张 H100 GPU 上跑 DSv3 671B、checkpoint 间隔 50 的规模下，我们测得以下改进：
